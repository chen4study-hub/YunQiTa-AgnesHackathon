# 公开文字清理与LLM措辞计数核对

## 本轮操作

- 清除公开文字中的星期/节日名，以及情景、典型日、代表日、估计、高温日、节假日、国庆等；保留预测/计算的非实测与范围限制。
- /chat、/chat/stream、/schedule支持可选display_date。未传不展示绝对日期；传入后由宿主将核验的今天/次日时刻装饰为指定日期/指定日期+1，不动原时间戳或预测、控制、费用。详docs/live_display_date.md。
- 扫描5093个公开字符串；三天导出修改12个文本字段（normal6、peak4、abstain2），其他导出无须改动。原始控制、经济、来源及时间戳保持相同。0新增LLM调用、0新增下发，未重跑13日评测。SHA及逐项不变验证见live_display_refresh.json。

## normal措辞减少的实证原因

此前对话汇报的“normal LLM措辞14/template10”不符合提交内容，应更正。直接读取773db56、c28a18e的normal导出及对应agent_replay_export回执，均为LLM措辞12、模板措辞12、规则0。907a450则为LLM措辞7、LLM选案但模板措辞12、规则5；当前清理不改变来源。

|版本|LLM措辞|LLM选案/模板措辞|规则回退|LLM选案总小时|
|---|---:|---:|---:|---:|
|773db56 / c28a18e|12|12|0|24|
|907a450 / 本轮|7|12|5|19|

因此可核实的净变化为12→7（不是14→7），规则回退新增5小时，模板措辞总小时数没有增加。具体回退记录：

|01:00|grounding_failed|
|02:00|HTTPStatusError，500，call_failed|
|08:00|grounding_failed|
|17:00|HTTPStatusError，500，call_failed|

两个批次独立真实调用，逐小时也不是简单一一流转，不能说旧5条LLM文字被容差直接替换。容差版新增“不可为容差内峰差多付费”防护及口径提示，确实可以使合格选案保留而措辞改template；此外日期、英文动作、精度/格式等同样可触发模板。保存状态只有explanation_mode=template，未记录每个模板小时的具体触发项，也未保存失败原文，无法事后断言各自原因或归因为LLM能力退化。被拒草稿/grounding失败的深层内容原因同样不猜测。完整计数可由refresh脚本重算。

验证：330项测试通过（137+193，限制native线程并拆分进程；一次不限线程运行出现Windows原生访问异常，读堆栈后改为限线程复核）。新增62项覆盖禁词/星期/节日、JSON/SSE、display_date非法输入、跨年/闰日、绝对日期不会取源年份、未来源数值仍拒绝、导出仅文本不变项。凭据扫描结果见live_display_refresh.json。

本轮不为了提高LLM措辞比例放宽grounding、不重试替换失败结果，不更改峰值容差、控制策略或经济模型。常驻后端尚未重启，未修改twin。
