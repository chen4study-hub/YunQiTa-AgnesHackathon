# 现有链路修复（v3继续默认关）

## 改动
- 新只读 `tariff_periods`（中文：分时电价与用电）：每小时已配置电价、峰平谷中文名、整栋负荷、电网功率、储能功率/充放电中文动作、小时电费。下午/上午/晚上或显式 start_hour/end_hour 选范围。电价高低与小时电费高低分别回答；时段问题不再进累计电费，改温度和累计路由不变。
- 数据口径：只读 ops 与 configs/agent_tools.json，不更改导出。当前配置电价并非已核验现场结算电价；正文明确“已配置分时电价”。ops 小时电费=整栋小时用电量×单价，工具校验这个等式，不能改说成扣除光伏/储能后的账单。未结束时段可做范围比较，但不冒充已发生累计电费。
- 因单价0.35元需要两位小数，展示改用35.0分/kWh（data仍保留0.35元/kWh），避免一位小数舍入改变费率。
- 楼宇正文流首token等待8→12秒；响应层每秒progress维持原id/文字，分类/工具阶段同样生效。普通知识原来15秒首token上限未改；工具选择结构化6/8秒期限未改，勿混算。
- 工具事件补name中文字段，不改原tool/args/事件名称。新工具纳入v3 energy目录仅保证可达，默认开关仍关，本提交不修改v3循环行为。

## 20秒卡点调查
原guard已用独立线程分类，然后立即advance pipeline，读本楼工具及正文请求与分类重叠；没有先等分类才读工具的串行问题，本轮不重复引入分类线程。新增done.classification_timing（budget_seconds/elapsed_ms/pipeline_ms/answer_ready_ms/answer_gate_wait_ms）区分正文完成与政策等待。公开web/city仍必须分类none后执行，正文一律等分类结果，涉政/时事同session终止规则未改变。

新真实数据确认：27层CO₂工具正文62ms已就绪，分类20015ms，正文等待19953ms；调度理由正文5797ms、分类20000ms；便宜时段正文63ms、分类20000ms。20秒是分类总预算到期及保守分类fallback，**不是工具串行**。不擅自缩短守卫或用关键词绕过它，因此少量20秒卡点仍存在。

离线阻塞测试使classifier必须等tool标志才返回，证明工具与分类确实并行；分类未完成时answer_delta未外发。分类等待统计截于分类实际完成，不把正文完成后的其它阻塞误算成分类等待。
