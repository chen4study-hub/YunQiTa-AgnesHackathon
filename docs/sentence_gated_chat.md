# 关键词工具路由与核验句流

## 路由与传输

命中时间、天气、储能电量、调度理由、转人工、执行回执、峰值或指定温度比较时，宿主直接执行对应只读工具，不等待LLM选工具。拿不准的 unknown 才请求结构化选择。时间/日期也由LLM组织文字，显示时钟仍由宿主提供且严格核验。

真实 provider 调用 `/chat/completions` 的 `stream=true` 普通文本输出，解析上游SSE的delta.content，不再等待完整tool-call JSON。最多450 tokens，30秒总问题预算；组合问题共用预算。超时不重试，只有快速HTTP500在尚未开启成功内容流时退避0.5秒重试一次；一旦开启内容流不会重放请求。有限并发槽和有限队列，超时取消消费，工作线程关闭生成器后释放槽。

## 句子门控与补充

原始片段仅进入内存缓冲；遇到句号/问号/叹号/换行才组成句子。检查数字来源、数字单位、时钟/日期、拒绝状态、日志回执边界、天气当前/未来范围、比较接受时段口径和无效交易话术。失败句不推送；完成的核验句立即成为 `answer_delta`，不等流结束。尾部未完成句仅在正常完成流后校验，不在中断时输出。

数字清单保留含义，回执明确列count、elapsed_ms、dispatch_target=BA/EMS和receipt_kind=下发日志回执。LLM必须引用条数、耗时及下发对象。晚到的缺必需值不再重新请求整段LLM，宿主在步骤中列缺值，末尾只补核验话句/必要范围，`sentence_source=template`。LLM句的delta标记 `sentence_source=llm`；phase记录accepted_llm_sentences与host_supplemented。

`explanation_source=llm` 表示至少有一句核验LLM内容，不代表每句都来自LLM。全无核验LLM句为template；部分流失败但已有核验句则保留已发送内容，并从工具补齐未满足信息，同时保留失败原因。JSON问答消费相同管线，SSE逐句推送，两者最终拼接一致。

费用句必须明确接受时段/非全天；无反对该口径的句可由宿主加简短已核验范围前缀。次日峰值可加“本次可用预测小时内”范围前缀，不猜完整全天。明确说全天收益或未连接实物已执行的句仍拒绝。金额节省必须匹配比较工具savings_cny，不借风险评分等同值冒充收益。末尾补充也进行数字来源校验。

## 运维理由展示

公开文字不写峰值容差、不可见微差、只执行首步后重规划。按“选用电费较低的方案/储能为峰段留电/拒绝时段保持设定且需复核”表达，一事一次，不重复后续拒绝段；分号后清空格。内部policy、指标、控制量、约束、SOC和费用不变。

导出由scripts/refresh_compact_prose离线处理，receipt=operator_reason_refresh，无新LLM调用、无下发、非文字字段不变。看板同步副本/About仍不在本轮修改范围。
