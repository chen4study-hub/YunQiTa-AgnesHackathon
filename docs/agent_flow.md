# Agent candidate-selection flow

src/agent/orchestrator.py exposes run_agent(forecast,context,constraints=None,provider=None,dispatch_path=...). Inputs are explicit deterministic tool outputs; no LLM-fetching hidden data. All three typical-day hourly replays call this with current+next-hour historical cache, dispatch_current_only=True, exports current plan, receipt and work order. Abstain day is now Independence Day2017-07-04, with mixed refusal/dispatch and10h refusal. Local per-hour checkpoint avoids repeating completed real calls/dispatches when resuming an interrupted export. Lookahead cache is retrospective one-step evidence, not a validated two-hour online forecast. This callable is implemented/tested; existing /schedule remains its prior one-hour compatibility flow and is not silently switched to requiring replay context.

Two fixed candidates use full/half shaving demand. Valley charges100/50kW subject to capacity and hard limits. Peak shaving demand=max(0,interval upper-PV-peak target800kW), clipped to500kW and available SOC; target may be explicitly configured. Before a following high-load hour, setpoint drops from25.5 to24.5C, one degree. This rule is a preparation scenario, not a thermal storage physics guarantee. Every candidate passes full-horizon check_constraints and simulate_schedule on accepted hours. Refused hours use25.5C/zero battery and work orders based only on explain_uncertainty evidence, with checks for meters, weather/interval and operational records, not asserted equipment failure.

When no hours refuse, LLM chooses only between validated candidates; cannot create controls. Choice validates via Pydantic; numeric reason grounding requires each numeric token to match a numeric tool-output leaf rounded to one decimal and the reason to include the upper-interval preparation amount. LLM freely writes one or two explanatory sentences about choice/actions; no fixed sentence requirement. Rounding applies only to the LLM evidence view/product text, not control feasibility or original model outputs. Format/grounding failure prompts one rewrite, then rule template. Demo/mock uses deterministic choice without HTTP and follows the same validation/simulation/dispatch pipeline. Real-choice transport failures are rule-source fallback with safe exception-class/status-code metadata, no exception body or secret logging. Grounding failures separately record grounding_failed. Demo/mock source maps to replay mock; validated real success maps llm.

If any hour refuses, the horizon bypasses the LLM; accepted hours may still dispatch the rule candidate. Refused hours never call dispatch_to_bms. Sink splits accepted controls into BA setpoint and EMS battery log entries, returns count and elapsed_ms; transport log_only/device_connected=false. Pydantic validates command/result before logging. No hardware network, no observed savings claim.

Grounding checks numeric consistency, not semantic entailment or causal truth. Simulation costs remain unvalidated linear estimates. Mixed-horizon simulation covers accepted hours, with SOC checked across all hours including handoff pauses; it must not be presented as full-horizon savings. Existing replay exports are unchanged. Tests cover demo full flow, charging/shaving/precooling, BA/EMS receipts, refusals, retries, grounded reasons and fallback.
