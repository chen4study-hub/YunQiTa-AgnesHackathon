# 调度温度优化与人工参考契约

## 规划规则

- 每个候选均进行逐小时温度优化，设定范围为设备约束与 24–27 °C 的交集；设定落到 0.1 °C 网格后重新校验费用、双峰值及舒适预算，避免小数尾差。
- 峰前允许预冷、峰段适度上调；舒适目标是 25.5 °C。费用目标加温度偏离的二次惩罚（系数 0.015 × 窗口负荷中位数（峰段取峰段中位数与全窗中位数的较大值）× 室外热度权重），室内温度超出舒适范围另加二次惩罚（系数 0.1 × 相同的负荷中位数）。室外热度权重为 1 + 0.07 × max(0, 室外温度 − 30)。室内温度沿用当前配置与已提供的室外温度，逐小时舒适上限限制峰段最高设定。分时电价与当小时负荷共同决定费用目标，避免惩罚系数与小时负荷相消而产生两档恒温。峰前 1–2 小时搜索 24.5–25.0 °C，峰段搜索 26–27 °C，其他时段可舒适放宽至 26 °C；费用峰值或舒适不允许时保留后备。
- 预冷分支覆盖紧邻峰段的两小时，用峰段平均升温对前两小时降温之和的 4:1 预算作为调度约束；不再将需求随峰段小时数累加，不宣称它是已标定的建筑蓄冷参数。若预冷会抬高原候选峰值，则单独优化峰段上调；不为预冷增加峰值。
- 原候选始终作为后备。只接受预计电费、点值购电峰值、区间上界购电峰值均不增加，且费用加舒适惩罚降低的结果。比较采用完整精度，数值容差为 1e-7。
- 自动候选的转人工小时仍为 25.5 °C、0 kW；这些小时不纳入自动收益比较。
- 最终选择还有跨候选保护：不满足旧政策赢家三项指标上限的候选仍展示，但不参与胜出比较；符合条件后继续按既有峰值容差和电费规则选案。72 个窗口的最终选择也无三项指标增加。
- 储能功率轨迹不因温度优化改变；仍保持功率、逐小时电量及窗口末电量约束。求解器边界误差用整条功率轨迹的安全缩放消除。

## 新增字段（兼容旧数据，导出字段为可选）

### `agent.manual_reference: array`

运行结果及详情只含当前窗口转人工小时；没有转人工小时则为空。主文件每小时仅保留时间戳等于本小时的那条，最多一条；整窗参考仅在详情。导出用逐小时 `agent.status` 重算连续段及剩余时长，而不是各自预测窗口中的拒绝段。`align_export_segments(data)` 在拆分前调用。

每条包含：

| 字段 | 含义 |
|---|---|
| `timestamp` | 带时区的建议小时 |
| `hvac_setpoint_c` | 建议设定温度，24–27 °C |
| `storage_mode` | `charge` / `discharge` / `idle` |
| `battery_kw` | 有符号功率，正放电、负充电，最大绝对值 500 kW |
| `suggested_duration_hours` | 所属连续转人工段的总小时数；不是固定功率的持续时间 |
| `remaining_duration_hours` | 从此小时到该段结束的剩余小时数 |
| `segment_start`, `segment_end` | 连续段起点与不含结束点的时间；允许跨日期 |
| `prepared_upper_kw` | 原始负荷区间上界 |
| `reference_soc_before`, `reference_soc_after` | 整个上界参考窗口中的小时起止电量比例 |
| `requires_confirmation` | 固定为 `true` |
| `reason` | 不超过 60 字的中文理由，含设定温度、功率或可用电量/峰段计划用电量及确认要求 |

人工参考独立复制预测，用区间上界作为规划负荷，储能功率采用设备限值的 50%，保留原电量上下界和窗口末备用电量。原预测、置信门控及自动执行计划均不改写。参考电量依据整个参考窗口，而非已下发轨迹；现场电量不符必须重新规划。该数组不进入下发函数。人工参考允许紧邻未来两小时峰段的平段补电，仍由上界峰值、电价和电量约束决定是否采用；电量已够时待机，理由明示关键数字。

查询函数：

```python
from src.agent.manual_reference import manual_reference_at
reference = manual_reference_at(agent, '2026-10-12', 14)
```

按时间戳中的当地日期和小时匹配，返回副本；不存在则返回 `None`。小时必须是 0–23 的整数；重复当地小时拒绝歧义查询。

### `agent.candidates[].temperature_optimization`

主数据的 `agent.candidate_summaries[]` 同样保留此对象；详情保留完整精度。

- `before`, `after`：各含 `energy_cost_cny`、`point_grid_peak_kw`、`upper_grid_peak_kw`，无通过门控小时则为 `null`。
- `applied`：是否接受温度改动。
- `comfort_penalty`：`quadratic_deviation_from_25.5`。
- `comfort_penalty_cny_per_kw_degree2`：0.015。
- `comfort_excess_penalty_cny_per_kw_degree2`：0.1。
- `precool_warming_budget_ratio`：4.0。
- `precool_budget_basis`：`mean_peak_warming_over_two_prepeak_hours`。
- `setpoint_step_c`：0.1。
- `scope`：`accepted_hours`。
- `selection_guard_passed`：能否在不增加旧政策赢家的预计费用、点值峰值与上界峰值的前提下参加最终选择。
- `selection_guard_caps`：旧政策赢家的上述三项完整精度指标；这两个字段仅在自动候选上提供。

相关契约：`contracts/replay.schema.json`、`contracts/replay-1.4.schema.json`、`contracts/agent-detail.schema.json`。无版本号变更，旧数据仍可读。

## 验证及前后对比

运行 `python -m scripts.verify_planner_export`：只写操作系统临时目录，结束自动删除；无服务调用、无自动下发，不改既有导出。验证 72 个窗口、主数据与详情契约、完整精度还原，并在临时目录生成逐候选 `comparison.json`。

2026-10-12 验证：199 个保留候选全部降低预计电费，点值峰值及上界峰值不增加；214 个转人工小时有独立参考，下发数为 0。保留候选共出现 53 个预冷小时，所有设定均符合 0.1 °C 网格。

| 候选 | 预计电费/元，前 → 后 | 点值峰值/kW，前 → 后 | 上界峰值/kW，前 → 后 |
|---|---:|---:|---:|
| rule_full | 15172.3 → 14700.4 | 1162.0 → 1128.3 | 1179.9 → 1172.3 |
| rule_conservative | 15172.3 → 14700.4 | 1113.0 → 1095.5 | 1179.9 → 1161.4 |

费用及峰值是现有配置模型下的预计指标，不代表已经取得的实账收益。全天恒定价格、无峰段时可以保持 25.5 °C；人工建议不保证每小时都有非零储能功率。
