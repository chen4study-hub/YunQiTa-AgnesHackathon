# LLM provider integration

Local Agnes configuration: ignored workspace .env selects auto, Agnes base/model and a key-file path; no key was copied into repository. One actual connectivity call succeeded, status real/configuration_complete. No response text or credential content was printed. Local .git/hooks/pre-commit is installed via scripts/install_precommit.py; it runs scripts/check_staged_secrets.py against staged blobs and blocks long provider-token patterns without printing matches. Hooks are local and must be installed separately on another clone; installer refuses to overwrite an existing hook.

python-dotenv loads workspace .env once on provider import, override=False; absent file is normal. Environment changes take precedence. LLM_API_URL is removed; LLM_BASE_URL is your configured OpenAI-compatible base, with /chat/completions appended. There is no hardcoded vendor endpoint or default model. Base/model come only from dotenv-loaded configuration or process environment; timeout defaults30seconds (valid range0-300exclusive/inclusive).

LLM_MODE=demo forces deterministic preconfigured replies and never reads a key file or creates an HTTP client, even with complete credentials. Missing/partial configuration defaults to demo. With complete base/model/key, auto or real uses real. Explicit mock is still supported offline. Explicit real with incomplete configuration returns demo with a generic warning. .env.example uses demo for public demonstrations. get_llm_status returns only mode/reason: configured availability, not a provider reachability guarantee or last-request status. One failed call falls back only for that request, reason=call_failed; later calls retry real. Failure exception bodies are never logged.

Mock returns deterministic hold/human_review commands, battery0, comfort midpoint, no remote call. Real uses one propose_plan tool call through OpenAI-compatible chat completion. Application still checks constraints and rejects unsafe commands; low-confidence hours bypass the provider. Successful provider output is redacted for exact API-key echoes before any downstream return/log. Request metadata includes llm mode/reason in schedule and dispatch records, and explain text carries mode/reason. /health preserves status/model_ready and adds llm.

LLM_API_KEY_FILE reads a UTF-8 single-line key; relative paths resolve from workspace root. Direct LLM_API_KEY takes precedence. File reads are bounded16KiB; missing/unreadable/empty/multiline files return only key_file_unavailable, never path/content/exception details. Put files under ignored secrets/ or use *.key. No key is returned by health.

Tests cover demo forced-offline with complete configuration, partial config, no vendor defaults, key-file transport/redaction/failure and direct-key precedence, plus mock determinism, generic warnings, real HTTP contract, per-request fallback/retry, missingdotenv, and abstention. No actual external provider call or real credential validation was performed; real integration is transport-contract tested.
